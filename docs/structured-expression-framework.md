# Structured Expression Framework (结构化表达逻辑模型)

为消除表达混乱、建立高信噪比的信息通道，智能体在方案规划、任务汇报、文档沉淀、方案答辩等交互场景中，强制推行以下四大表达逻辑模型：

1. **PREP 模型（微观单点逻辑论证）**:
    - **核心定位**：解决“说话抓不住重点、论据脱节”问题，训练严密的单点线性逻辑思维；
    - **四步链路**：
      - **P (Point - 结论先行)**：开门见山亮出核心论点或操作建议，一句话击中要害；
      - **R (Reason - 原理/依据)**：阐明因果逻辑，给出支撑观点的核心理由与机制依据（解释 Why）；
      - **E (Example - 举例佐证)**：给出具体的工程案例、实操现象、对比数据或代码片段（具象化支撑）；
      - **P (Point - 重申闭环)**：总结升华，再次呼应强化核心论点，并提出行动建议或号召；
2. **金字塔结构（中观系统性思维）**:
    - **核心定位**：适用于多内容、高维度的复杂系统汇报、架构设计与长篇文档，训练立体化系统性思维；
    - **架构法则**：
      - **塔尖定调**：以唯一的最高层核心结论为塔尖（自上而下，结论先行）；
      - **MECE 拆解**：向下拆解为 3 个左右**相互独立、完全穷尽（MECE，不重不漏）**的逻辑层级与支撑维度（按时间时序、空间结构、重要程度或演绎逻辑展开）；
      - **纵向疑问解答**：每一层级均作为上一层级的答疑与支撑，层层递进、纵向贯通无逻辑断层；
3. **SCQA 模型（宏观序言与破局吸引力）**:
    - **核心定位**：打破受众心智防御，极大提升方案呈现、立项开篇与技术汇报的吸引力与推进力；
    - **叙事四部曲**：
      - **S (Situation - 共有情境)**：描述受众熟知且认同的客观背景与稳定现状，拉齐沟通基准；
      - **C (Complication - 冲突/痛点)**：引入突发变数、严峻痛点、环境变化或危机瓶颈，打破平衡，激发紧迫感；
      - **Q (Question - 核心问题)**：顺理成章推导出受众最关心的核心疑问（“面临该冲突，我们该怎么办？”）；
      - **A (Answer - 破局答案)**：顺势引出解决方案、系统决策或技术行动建议；
    - **高阶倒推与灵活变体**：麦肯锡咨询精髓在于“**思考时由答案 A 倒推冲突 C 与情境 S**”，反向萃取最高效的证据链；表达时可根据受众心理灵活调整顺序（如向上汇报采用开门见山式 `A-S-C-Q`、争取资源采用危机警醒式 `C-S-A-Q`、常规呈现采用标准叙事式 `S-C-Q-A`）；
4. **STAR 模型（实证还原与沉浸感故事）**:
    - **核心定位**：用过去的客观事实与行为还原预测未来工程能力，增强故事复盘的沉浸感与可信度；
    - **复盘四要素**：
      - **S (Situation - 背景)**：交代项目或事件发生的时间、技术环境与客观约束；
      - **T (Task - 任务)**：明确当时面临的核心挑战、关键瓶颈与考核指标；
      - **A (Action - 行动)**：**叙事的核心骨架（权重通常占 50%-60%）**，详述决策思考过程（Why & How）、攻坚动作与资源权衡；
      - **R (Result - 结果)**：交代最终量化产出、交付成效、积极影响及复盘沉淀的方法论；
    - **动态重心调控**：根据沟通目的动态调配权重——展示技术实力与决策深度侧重 `Task + Action`，展示业务落地的商业价值侧重 `Result`（突出量化数据），展示危机应对与抗压韧性侧重 `Situation + Action`；

**各模型既各司其职，又可深度嵌套协同，且必须在实践中高频刻意练习以沉淀为肌肉记忆**：

1. **Composite Nesting Architecture (多模型复合嵌套架构)**:
    - 四大模型严禁机械割裂，在复杂交互与技术输出中须融会贯通为“俄罗斯套娃”式系统矩阵：
      $$\text{SCQA (顶层序言破局)} \xrightarrow{\text{以 A 导出核心方案}} \text{金字塔结构 (中层 MECE 骨架)} \xrightarrow{\text{子模块细化展开}} \text{PREP (段落逻辑闭环)} \xrightarrow{\text{E 举例环节}} \text{STAR (实证还原)}$$
2. **Deliberate Practice (实战刻意练习定式)**:
    - 表达逻辑是刻在工程骨子里的肌肉能力而非静态教条。在每次规划（Plan）、验证自证（Walkthrough）、代码评审（PR/Commit）、根因复盘（Issue）及日常交互中，均须自觉以该体系对照检视，在实操中实现持续熵减。
