# Content Currency Specifications (内容现行态规范)

> **文档定位**：本文是 Content Currency (内容现行态) 的**唯一详尽来源 (Single Source of Truth)**。[AGENTS.md](../AGENTS.md) 中仅保留摘要级指针，判定准则、豁免边界与可执行判据以本文为准；信息序与结构骨架以 [Structured Expression Framework](./structured-expression-framework.md) 为准，术语取舍以 [Terminology Specifications](./terminology-specifications.md) 为准。本文自身的演变痕迹仅由 Git 历史承载。

---

## 🎯 适用范围与判定流程 (Scope & Decision Flow)

治理对象为**一切文档正文**（含 README、附录章节、图表内文字）。Commit message 与 PR 正文是 Git/平台原生的变更叙事载体，代码注释由 [AGENTS.md](../AGENTS.md)「Comments」条目治理，均不在本规辖域。

```
                ┌────────────────────────────────────┐
                │        正文出现疑似版本叙事        │
                └─────────────────┬──────────────────┘
                                  ▼
        ┌─────────────────────────────────────────────────┐
        │ 位于专用变更记录载体？（独立文件，且以记录变更为  │
        │ 唯一职责：项目级 CHANGELOG、issue.md 等）         │
        └───────────┬───────────────────────┬─────────────┘
                    │ 是 (YES)              │ 否 (NO)
                    ▼                       ▼
          ┌─────────────────┐   ┌───────────────────────────────────┐
          │   合法承载      │   │ as-of 戳，且仅锚定外部事实/数据/  │
          │  （载体豁免）   │   │ 引用的时效，无对本文件的改版叙述？│
          └─────────────────┘   └─────────┬──────────────┬──────────┘
                                          │ 是 (YES)     │ 否 (NO)
                                          ▼              ▼
                                ┌───────────────┐ ┌─────────────────────┐
                                │  合法锚定     │ │“既有术语 → 现行结构”│

                                └───────────────┘ │术语体系？           │
                                                  └─────┬─────────┬───┘
                                                        │ 是      │ 否
                                                        ▼         ▼
                                               ┌────────────┐ ┌────────┐
                                               │ 合法投影   │ │ 判违规 │
                                               │（映射豁免）│ │        │
                                               └────────────┘ └────────┘
```

**双命中裁决**：豁免形态与禁止叙述同时命中时，一律以**禁止叙述优先**裁决（体裁对齐 [Plain Language Specifications](./plain-language-specifications.md)「裁决层级」）。

## 🚫 四类禁止形态 (Forbidden Forms)

| # | 形态 | 识别要点 | 负例（判例样本） |
| :- | :--- | :--- | :--- |
| 1 | “日期 + 重铸/改版/换代”式叙述 | 日期与改版动词共现，宾语为文件自身 | “**2026-10-10 完全重铸**：2026-09-27 版 §0–§15 退役封存勿复用”（negentropy 013 蓝图判例，2026-10 实测，沿引用链扩散 7 文件 12 处） |
| 2 | 新旧节号对照与换算 | “旧 §N → 新 §M”映射或“相当于/对应”式换算 | “旧 011 §3 相当于现行 §5”（同上引用链） |
| 3 | 版本退役/封存声明 | 宣告旧版本/旧方案作废、封存、勿复用 | “v1 已于 2026-06-30 退役封存” |
| 4 | 迁移记录 | 叙述本文件内容/结构/工具链自旧至新的搬迁 | “驱动迁移：从 A 驱动迁移至 B 驱动” |

四类形态共享同一宾语限定：**文件自身（含同仓其他文件）的历史**。面向用户的产品/接口迁移指引（宾语为产品版本）与外部仓库的版本事实（经 as-of 戳锚定）不在此列。

## ✅ 专用载体豁免 (Carrier Exemption)

判定准则（须**同时**满足，缺一即回落正文管辖）：

1. **独立文件**：以单独文件存在；文档内任何形式的“演进记录/变更记录/修订历史”附录或章节同属正文，不构成豁免；
2. **唯一职责**：该文件以记录变更为唯一职责。

| 合法载体 | 依据 |
| :--- | :--- |
| 项目级 `CHANGELOG.md` | 独立文件、唯一职责（判例：negentropy commit b2fbb51f5 清零正文版本史的同时补记 CHANGELOG，证明其为合法承载面） |
| `docs/.agents/issue.md` | [AGENTS.md](../AGENTS.md) Operational Excellence「Issue」条目指定的 Issue 摘要载体 |
| release notes | 发布专用载体，同性质载体可按判定准则增补 |

## ✅ 两类合法性豁免 (Legitimate Exemptions)

### as-of 戳（证据时效）

- **形态**：截至日期/commit 指纹，如“截至 2026-10-10，基准结果为 X”“as of commit e719ae5”；
- **锚定边界**：仅可锚定**外部事实、数据或引用**的时效（基准结果、第三方版本、外部仓 commit 指纹）；句中不得携带对本文件自身的改版叙述与新旧对照；
- **合规**：“截至 2026-06-06，Playwright MCP 为 B 类场景默认驱动”（锚定外部工具事实）；**违规**：“截至 2026-10-10，本节已重铸”（借 as-of 戳夹带改版叙述，双命中，禁止叙述优先）。

### 投影映射（术语承接）

- **形态**：“既有术语 → 现行结构”；
- **两步宾语判定**：箭头左侧宾语须为**外部世界的术语体系**（外部论文/下游系统/共用词表），且不得为本文件自身的历史节号或历史版本产物；
- **合规**：“下游系统 V2 contract → 本文「工具职责矩阵」”；**违规**：“旧 §5 → 现行 §3”（宾语为本文件历史节号）。

## 🔍 可判定性与 grep 判据 (Detectability)

| 判据 | pattern（示意，ERE） | 口径 |
| :--- | :--- | :--- |
| 日期 + 改版动词共现 | `[0-9]{4}-[0-9]{2}-[0-9]{2}[^。]{0,12}(重铸\|改版\|换代\|重写\|重构\|重组\|翻新)` | L3 可机械检索 |
| 演进记录类章节 | `^#+ .*(演进记录\|变更记录\|修订历史\|版本历史)` | L3 章节级直接命中 |
| 新旧节号对照 | `(旧\|原)[^。]{0,6}§ ?[0-9]+[^。]{0,10}(→\|相当于\|对应)` | L3 可机械检索 |
| 退役/封存声明 | `(退役\|封存\|作废)[^。]{0,8}(版本\|方案\|旧)` | L2 命中后人工审宾语 |
| as-of 夹带 | `截至[^。]{0,30}(重铸\|改版\|重写\|重构\|换代)` | L2 双命中即违规 |

**工程教训（本规约评审实测）**：验证 pattern 必须按**语义族**展开，不能只用规则原文词——规则写“迁移记录”时，存量违规实际使用“驱动迁移”“废弃”“重组”等同义表述，按原文词检索会得到“零违规”假阴性。上表动词族按此原则维护，新增同义词应入表而非散落。

## 🤝 与其他规范的分工

- **与 [AGENTS.md](../AGENTS.md)「Single Source of Truth」**：该法则禁数据副本（治引用方式），本规范禁版本叙事（治内容时态），同向强化；
- **与 [AGENTS.md](../AGENTS.md)「Issue」条目**：issue.md 经「专用载体豁免」合法承载 Issue 摘要，判定边界以本文为准；
- **与 [Plain Language Specifications](./plain-language-specifications.md)**：该规范治叙述性产出（含 Commit/PR 正文）的措辞质感，本规范治文档正文的内容时态，对象正交；规则冲突时按「双命中裁决」执行（禁止叙述优先）。
